# Reproducible QA (sandbox only)

Never run fixture seed, plugin-toggle, empty-state or Customizer tests on
production. Use a fresh local WordPress with `FF90_QA_SANDBOX=true` and a
non-production admin. Test helpers are excluded from the installable ZIP.
The theme itself requires no Node, SQLite or WP-CLI.

## Tools used for this run

- WordPress 6.9, tag commit ec24ee6087dad52052c7d8a11d50c24c9ba89a3b.
- PHP 8.4.24 CLI and pdo_sqlite / sqlite3 / mbstring / dom / xml / phar;
  Debian signed APT packages extracted under `/workspace/ff90-tools/php`.
  Package indexes and hashes verified by APT; TLS/signature checks retained.
- WordPress SQLite integration commit e88a817e89a80c4fab2b46f86606367822695b45
  (local sandbox only, not MySQL parity certification).
- WP-CLI 2.12.0; PHAR matched its published SHA-512.
- WordPress/theme-check commit 9c21ede71a1cd09aa2605f64da85e2f83822cf9d.
- Chromium 154.0.8037.57, playwright-core 1.64.1, @axe-core/playwright 4.14.0.
- Python 3 / Pillow for original synthetic fixture images and theme thumbnail.

The local root is `/workspace/ff90-tools/wordpress`; URL uses loopback port
8088 and is used only for QA, not as a user-facing preview. PHP uses four CLI
workers because the Customizer uses concurrent requests. Cron and outbound
updates are disabled only in the isolated QA WordPress config. No production
secrets or database copies are used.

## Prepare a fresh local instance

Install WordPress 6.9 using normal supported tooling. For SQLite, install the
WordPress SQLite integration and its `db.copy` drop-in following its official
instructions (it is not bundled in this theme). Put the SQLite file outside the
web root. MySQL/MariaDB staging can use a normal WordPress install instead.

Install/activate `wordpress-plugins/football-factory-core` and WordPress's
`theme-check` plugin. Install the FF90 ZIP. Set WordPress timezone to
Asia/Bangkok and permalinks to `/%postname%/`. Define `FF90_QA_SANDBOX=true`
only in this disposable site.

For the test scripts, `/workspace/ff90-tools/bin/wp` is a wrapper calling
WP-CLI with this site's path. Set `FF90_QA_WP` for a different wrapper and
`FF90_QA_NODE_MODULES` to your playwright/axe node_modules directory. Seed uses
synthetic PNGs from `/workspace/ff90-tools/fixtures/`, generated by
`python3 tests/make-fixtures.py`. Install optional Pillow first. Seed both
layouts with three stories per category, long Thai headlines, 13 original
banners, menus, a draft that must stay invisible, and a clearly labeled QA ad.

```sh
# Run from wordpress-themes/ff90-independent; substitute your php/wp wrappers.
python3 tests/make-fixtures.py
wp eval-file tests/seed.php
wp eval-file tests/wp-contracts.php
node --check assets/js/theme.js
find . -name '*.php' -not -path './docs/*' -print0 | xargs -0 -n 1 php -l
```

The browser runner expects a private local `install-private.log` containing the
sandbox-only generated password line from `wp core install`. It never prints
that password. A fresh install is required; do not supply production credentials.
The test-only plugin probe is symlinked/copied to
`wp-content/plugins/ff90-qa-probe.php` from `tests/plugin-probe.php`; it requires
the explicit sandbox marker and is deactivated after its test.

Start a normal local PHP-capable web server with WordPress rewrite support,
then run `node tests/browser.cjs`. The runner rejects non-loopback URLs and
missing sandbox marker; it switches layouts, toggles Core/probe plugins,
performs native Customizer login/save, checks images/overflow/canonical tags,
and runs axe on both layouts at 360/390/768/1024/1440 and inner pages. Test
results and real screenshots are written under `docs/qa/`.

## Verify the distributable, not the QA tree

```sh
python3 tests/build.py
# Install the ZIP in a separate real local WordPress theme directory.
wp theme install /absolute/path/dist/ff90-independent-1.2.0.zip --force --activate
wp theme-check run ff90-independent --format=json
```

Do not install over a symlink pointing into the source tree; remove only the
known test symlink first. Theme Check must scan the unpacked distribution:
repository-only test helpers intentionally contain test plugin operations,
reports and ZIPs and are not theme runtime code. The build allowlist excludes
all tests/docs/dist outputs. Retain the Theme Check exit status. Optional
recommendations are reported separately from required failures.

Build twice and compare SHA-256 to verify reproducibility. Inspect ZIP paths,
root folder, `style.css`, `index.php`, screenshot, LICENSE, and absence of QA
seeds/credentials. Re-run frontend QA against the installed ZIP after final
runtime source changes. Actual SEO Growth V4, Analytics and football-provider
adapters are NOT_RUN until their versions/data are supplied.

## Editorial feature and statistics regression (1.2.0)

Local PHP must include GD or Imagick for real Media Library upload/resizing
QA. This instance uses Debian-verified php8.4-gd. The server was restarted
with the extension enabled; WordPress itself uses the native image editor.

Install the separate FF90 News Insights ZIP; it never bundles with the theme:

```sh
python3 tests/build-insights.py
wp plugin install /absolute/path/wordpress-plugins/ff90-news-insights/dist/ff90-news-insights-1.0.0.zip --activate
wp eval-file tests/editorial-setup.php
python3 tests/make-fixtures.py
wp eval-file /absolute/path/wordpress-plugins/ff90-news-insights/tests/contracts.php
node tests/editorial-features.cjs
```

The setup helper is sandbox-only and configures the user-approved public
contact email without fabricating social accounts. Contract tests create and
remove their own rows/posts. Browser tests use synthetic QA news/banner and
two real local request contexts to verify increment/dedup/exclusions; no test
event is described as real readership. The media test actually opens the native
Media Library tab, chooses an image, edits its URL, publishes, and checks the
rendered image ratio. Responsive srcset can choose a resized file, so the
assertion checks full-frame ratio/contain rather than forcing original pixels.
Temporary creative/settings/posts/statistics are restored/deleted afterward.
